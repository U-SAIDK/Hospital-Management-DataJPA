# Cheat Sheet

Terse lookup tables for this project. Paths are under
`src/main/java/com/codingshuttle/youtube/hospitalManagement/` unless noted. For the *why*, follow the
concept file in `NOTES/` or `src/MASTER_NOTES.md`.

---

## 1. Annotation reference

| Annotation | What it does | Example in this project (file) |
|---|---|---|
| `@Entity` | Marks a class as a JPA-managed table row type | every `entity/*.java` (`Patient`, `Doctor`, `Appointment`, `User`, `Department`, `Insurance`) |
| `@Id` | Marks the primary-key field | `Patient.id`, `Doctor.id`, `Appointment.id`, `User.id`, `Department.id`, `Insurance.id` |
| `@GeneratedValue(strategy = IDENTITY)` | DB auto-increments the PK on INSERT | `entity/Patient.java` `id` (and all other entities) |
| `@Column` | Customizes the column (nullable, length, unique, updatable) | `Patient.name` (`nullable=false, length=40`), `Patient.email` (`unique=true, nullable=false`), `Appointment.reason` (`length=500`), `Insurance.createdAt` (`updatable=false`) |
| `@OneToOne` | 1:1 association | `Doctor.user`/`Patient.user` (`@MapsId`), `Patient.insurance` (owning, `@JoinColumn`), `Insurance.patient` (inverse, `mappedBy`), `Department.headDoctor` (unidirectional) |
| `@OneToMany` | 1:N, "one" side; needs `mappedBy` on the inverse | `Patient.appointments` (`mappedBy="patient"`, EAGER override), `Doctor.appointments` (`mappedBy="doctor"`, LAZY default) |
| `@ManyToOne` | N:1, "many" side, holds the FK | `Appointment.patient` (EAGER default), `Appointment.doctor` (explicit LAZY) |
| `@ManyToMany` | N:M association | `Department.doctors` (owning, `@JoinTable`), `Doctor.departments` (inverse, `mappedBy="doctors"`) |
| `@JoinColumn` | Names the FK column on the owning side | `Appointment.patient` (`name="patient_id", nullable=false`), `Appointment.doctor` (`nullable=false`), `Patient.insurance` (`name="patient_insurance_id"`) |
| `@JoinTable` | Defines the M:N join table (owning side) | `Department.doctors` — `name="my_dpt_doctors"`, `joinColumns=@JoinColumn(name="dpt_id")`, `inverseJoinColumns=@JoinColumn(name="doctor_id")` |
| `@MapsId` | PK of this entity IS the associated entity's PK (shared key) | `Doctor.user`, `Patient.user` |
| `@ElementCollection` | Collection of value types (not entities), in a side table | `User.roles` (`fetch=EAGER`, `Set<RoleType>`) |
| `@Enumerated(EnumType.STRING)` | Persist enum by name, not ordinal position | `Patient.bloodGroup`, `User.providerType`, `User.roles` |
| `@Transactional` | Runs the method in a DB transaction (atomic, keeps entities managed) | `AppointmentService.createNewAppointment`/`reAssignAppointmentToAnotherDoctor`, `DoctorService.onBoardNewDoctor`, `PatientService.getPatientById`, `InsuranceService` assign/disassociate, `AuthService.handleOAuth2LoginRequest`, `PatientRepository.updateNameWithId` — all `jakarta.transaction.Transactional` |
| `@Modifying` | Marks a `@Query` as DML (UPDATE/DELETE), not a SELECT | `PatientRepository.updateNameWithId` |
| `@Query` | Custom JPQL or native SQL for a repository method | `PatientRepository.findByBloodGroup`/`findByBornAfterDate`/`countEachBloodGroupType`/`updateNameWithId`/`findAllPatientWithAppointment` (JPQL), `findAllPatients` (native) |

**Related supporting annotations seen here:** `@Table` (`Patient` name+constraints+index, `User`
`app_user`+index), `@UniqueConstraint` (`Patient` `(name, birthDate)`), `@Index`
(`idx_patient_birth_date`, `idx_provider_id_provider_type`), `@CreationTimestamp` (`Patient.createdAt`,
`Insurance.createdAt`), `@ToString.Exclude` (`Appointment.patient`/`.doctor`).

## 2. FetchType defaults (and where this project follows vs overrides them)

| Relationship | JPA default | Follows default | Overrides default |
|---|---|---|---|
| `@OneToOne` | EAGER | `Patient.user`, `Doctor.user`, `Department.headDoctor`, `Patient.insurance`, `Insurance.patient` | — |
| `@ManyToOne` | EAGER | `Appointment.patient` (no fetch attr → EAGER) | `Appointment.doctor` → `fetch = LAZY` |
| `@OneToMany` | LAZY | `Doctor.appointments` (`mappedBy="doctor"`, no fetch attr → LAZY) | `Patient.appointments` → `fetch = EAGER` |
| `@ManyToMany` | LAZY | `Department.doctors`, `Doctor.departments` | — |

Mnemonic: **to-one = EAGER, to-many = LAZY** by default. The two deliberate overrides
(`Appointment.doctor` → LAZY, `Patient.appointments` → EAGER) are teaching contrasts, not
recommendations. `User.roles` is `@ElementCollection(fetch = EAGER)` — EAGER because
`getAuthorities()` reads it outside the session. See `NOTES/11` and `NOTES/14`.

## 3. CascadeType options

| CascadeType | Meaning | Used in this project? |
|---|---|---|
| `ALL` | Applies PERSIST, MERGE, REMOVE, REFRESH, DETACH — the child's whole lifecycle follows the parent | **Yes** — `Patient.insurance` (`cascade = {CascadeType.ALL}`) |
| `PERSIST` | Saving the parent saves the child | (only via `ALL`) |
| `MERGE` | Merging the parent merges the child | (only via `ALL`) |
| `REMOVE` | Deleting the parent deletes the child | **Yes** — `Patient.appointments` (`cascade = {CascadeType.REMOVE}`); also via `ALL` on `Patient.insurance` |
| `REFRESH` | Refreshing the parent refreshes the child | (only via `ALL`) |
| `DETACH` | Detaching the parent detaches the child | (only via `ALL`) |

Only `ALL` (`Patient.insurance`) and `REMOVE` (`Patient.appointments`) appear **explicitly** in this
codebase. No other cascade type is used standalone.

## 4. orphanRemoval

| Field | Declaration | Effect |
|---|---|---|
| `Patient.insurance` | `@OneToOne(cascade=ALL, orphanRemoval=true)` | Setting `patient.setInsurance(null)` DELETEs the `Insurance` row on flush (`InsuranceService.disaccociateInsuranceFromPatient`), not just nulling a FK |
| `Patient.appointments` | `@OneToMany(cascade=REMOVE, orphanRemoval=true, fetch=EAGER)` | Removing an appointment from the list deletes it; deleting the Patient deletes all appointments |

`orphanRemoval` = "delete the child when it leaves the parent's reference," stronger than
`cascade=REMOVE` (which only fires when the *parent* is deleted). See `MASTER_NOTES.md` §5.

## 5. Pageable / Sort / Page quick syntax

| Construct | Syntax | Example in this project |
|---|---|---|
| Page request (no sort) | `PageRequest.of(pageIndex, size)` | `PatientService.getAllPatients` → `PageRequest.of(pageNumber, pageSize)` |
| Page request (sorted) | `PageRequest.of(pageIndex, size, Sort.by("field"))` | `PatientTests.testTransactionMethods` → `PageRequest.of(1, 2, Sort.by("name"))` |
| Sort spec | `Sort.by("field")` (ascending) | `Sort.by("name")` in the test |
| Paged repo method | `Page<T> m(Pageable p)` | `PatientRepository.findAllPatients(Pageable)` (native, returns `Page<Patient>`) |

**Gotchas (see `NOTES/13`):** page index is **0-based** (`PageRequest.of(1, ...)` = 2nd page);
`Page<T>` fires an extra **COUNT query** for `getTotalElements()`/`getTotalPages()` (use `Slice<T>` to
skip it); `LIMIT`/`OFFSET`/`ORDER BY` are appended by Spring Data even for **native** queries.

## 6. Query mechanism quick reference (all from `PatientRepository`)

| Mechanism | Example method | Note |
|---|---|---|
| Derived (name-parsed) | `findByName`, `findByBirthDateOrEmail`, `findByBirthDateBetween`, `findByNameContainingOrderByIdDesc` | parsed once at startup |
| JPQL `@Query` | `findByBloodGroup` (`?1` positional), `findByBornAfterDate` (`:birthDate` named) | entity/field names |
| JPQL constructor projection | `countEachBloodGroupType` → `BloodGroupCountResponseEntity` | DTO built in query; ctor must match `SELECT new(...)` |
| Native `@Query(nativeQuery=true)` | `findAllPatients` | raw SQL against `patient` table; still paginated |
| Bulk DML | `updateNameWithId` (`@Modifying` + `@Transactional`) | bypasses persistence context |
| JOIN FETCH | `findAllPatientWithAppointment` (`LEFT JOIN FETCH p.appointments`) | N+1 fix, single query |

## 7. Owning vs inverse side quick reference

| Association | Owning side (writes DB) | Inverse side (`mappedBy`) |
|---|---|---|
| Patient ↔ Insurance (1:1) | `Patient.insurance` (`@JoinColumn`) | `Insurance.patient` (`mappedBy="insurance"`) |
| Patient ↔ Appointment (1:N) | `Appointment.patient` (`@JoinColumn`, the FK) | `Patient.appointments` (`mappedBy="patient"`) |
| Doctor ↔ Appointment (1:N) | `Appointment.doctor` (`@JoinColumn`, the FK) | `Doctor.appointments` (`mappedBy="doctor"`) |
| Department ↔ Doctor (N:M) | `Department.doctors` (`@JoinTable my_dpt_doctors`) | `Doctor.departments` (`mappedBy="doctors"`) |
| Doctor/Patient ↔ User (1:1 shared PK) | `Doctor.user`/`Patient.user` (`@MapsId`) | (unidirectional — `User` has no back-reference) |

Rule: the side with `@JoinColumn`/`@JoinTable` owns the FK and controls what's persisted; the
`mappedBy` side is for in-memory navigation/consistency only.
